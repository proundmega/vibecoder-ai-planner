🔎 IPEE Methodology
1. Identify
Define the problem clearly.

Separate symptoms from root causes.

Specify inputs, outputs, constraints, and edge cases.

Example: Problem — sort a list of integers. Inputs — unsorted list. Output — sorted list.

2. Plan
Brainstorm possible solutions or algorithms.

Evaluate feasibility, complexity, and resource requirements.

Select the most effective strategy.

Example: Options — bubble sort, quicksort, built-in sort. Chosen — built-in sort for efficiency.

3. Execute
Implement the chosen plan in code.

Follow best practices (readability, modularity, documentation).

Ensure responsibilities and steps are clear if working in teams.

Example: Write Python function using list.sort().

4. Evaluate
Test the solution against expected outcomes.

Use unit tests, edge cases, and performance checks.

Collect feedback and refine if necessary.

Example: Verify sorting works for empty lists, duplicates, negative numbers.

🛠 Implementation Guidelines
Always start coding sessions by explicitly stating the Identify step.

Document the Plan before writing code.

Ensure Execute is traceable (commit messages, comments).

Perform Evaluate before considering the task complete.

Repeat the cycle if evaluation shows gaps.

🚀 Example Workflow
Identify: "We need a function to reverse a string."

Plan: Options — manual loop, slicing, built-in functions. Choose slicing.

Execute: Implement def reverse_string(s): return s[::-1].

Evaluate: Test with "hello" → "olleh", empty string, single character.

✅ Benefits
Prevents rushing into coding without analysis.

Ensures solutions are tested and reliable.

Provides a repeatable framework for collaboration.

Encourages continuous improvement.

📌 Mandatory Rule
All coding sessions must use the IPEE methodology.  
Skipping any step is not permitted. This ensures consistency, quality, and accountability in problem-solving.
