## Deployment boundary (slice 1)

Docker mode currently requires an agent that runs on, or shares a workspace
path with, the Docker host. `PoolManager` still launches agents with only the
`HARNESS_*` environment and a named repo volume, and `agent/docker-compose.yml`
does not mount a daemon socket. Pool-launched agents therefore stay in host
mode until the deployment wiring lands. This is **D8** in the `00` deferred
register; it is not claimed as delivered here.

OpenCode still runs in the supervisor in slice 1. Only supervisor-driven
install/verification commands go through the sandbox; a prompt-injected
OpenCode `bash` call still executes on the supervisor until the slice-2
bridge. Operator docs state this explicitly.

### Coverage notes

- The prompt labels ticket, planning and repository content as untrusted, states that supervisor instructions and the publishing policy take precedence, and escapes the untrusted-content terminator. The built-in `read`/`grep`/`lsp` tools are disabled; `sandbox_read`/`sandbox_grep` call a loopback workspace bridge that resolves `toRealPath()`, rejects targets outside the workspace and the credential-path denies, and grep never follows symlinks (D18). The built-in `edit`/`write`/`multiedit`/`patch` tools are disabled (OpenCode 1.19.5 maps edit/write/apply_patch to the `edit` action; the extra keys are defense in depth); `sandbox_write`/`sandbox_edit` walk the path through `SecureDirectoryStream` descriptors with NOFOLLOW on every component including the final open, reject symlink targets and credential/VCS/control paths, bound the replacement size before allocation, and preserve BOM/CRLF for edits, closing D20 where secure directory streams are available. Read/grep use the same secure open helper. Native Windows or other providers without `SecureDirectoryStream` use a non-atomic canonical fallback in host mode; sandbox mode fails fast at bridge startup (D22; host mode is not a security boundary), and a FIFO final-component swap can still block an open (D23). The bash bridge denies a high-confidence subset of credential-file reads, interpreter one-liners, network uploads and `/dev/tcp`; it is a coarse regex denylist, not a shell parser (a `-F` token inside a quoted header value can false-positive, and encoded forms can bypass). The supervisor refuses to publish a guarded-tree changed blob whose content or new path contains a configured credential or a high-confidence credential format; it reads tree blobs directly so `.gitattributes`/binary/`++`-prefix/filename bypasses do not hide content, compares against the base blob so pre-existing fixtures in modified files do not block unrelated edits, compares complete PEM private-key blocks (case-insensitive BEGIN/END detection; exact block comparison, so reformatting/case-changing a pre-existing block counts as new), exposes new gitlink paths to the path scanner, and fails closed on a blob larger than the scan limit. A changed or base blob above the 8 MB scan limit fails closed; raising `HARNESS_MAX_BYTES` above that can reject a large modified file, and a diff-based scan is the future fix. Prompt injection remains probabilistic; the sandbox, secretless env and publishing guard are the boundary (FR8).
- CPU/PID enforcement is asserted through the `docker run` flags; the integration test asserts the memory cgroup bound. A behavioral CPU/PID stress test is deferred to slice 3.
- Supply chain (FR9): every base image in the supervisor, sandbox and proxy Dockerfiles is pinned by digest; `agent/scripts/sandbox-image-security.sh --check-pins` is the deterministic CI gate. The gate matches `FROM` case-insensitively, strips a leading UTF-8 BOM and CRLF, ignores references to earlier build stages and requires the digest on the image token (an inline-comment digest does not count). `--all` runs the same pin check before the SBOM/scan steps. `--sbom` uses syft (SPDX JSON under `agent/target/sbom/`), `--scan` uses trivy or grype with a HIGH/CRITICAL default, and `--all` optionally verifies a cosign signature when `COSIGN_PUBLIC_KEY` is set. CI builds and scans the supervisor, sandbox and proxy images and archives the SBOMs. SBOM/scan tools are optional locally; set `SANDBOX_SCAN_REQUIRED=1` in CI to fail instead of skipping. Scanner semantics differ: trivy uses `--ignore-unfixed` while grype has no equivalent and fails on any matching (including unfixed) finding. Node installs already use `npm ci` when a lockfile exists and `--no-package-lock` otherwise. Lifecycle scripts run inside the sandbox; a repo-profile opt-out is fg-39.
- The disk quota is enforced by a lifetime supervisor watchdog at `SANDBOX_DISK_CHECK_INTERVAL_SECONDS` granularity. Measurement failure (including per-file `visitFileFailed`) fails closed. Unlinked-but-open files are outside the supervisor walk and require a real FS quota (D12).
- The Docker file channel uses distinct non-zero exit codes for guard failures, so a same-UID stdout flood cannot mask them; successful guards also print `OK`/`OK <size>`. Downloads are sized inside the container before copying and use a temp file. The size and `docker cp` remain untrusted (D10).
- A pre-publish `destroy` failure fails the ticket and never stages or pushes; `DockerSandboxRunner.destroy` verifies removal and keeps tracking on failure. `close()` retries tracked containers and retains the shutdown hook while any remain; a hard-killed agent leaves cleanup to the D9 reaper.
- `SANDBOX_NETWORK=allowlist` creates a per-sandbox internal Docker network and a hardened proxy container (read-only rootfs, dropped capabilities, non-root, PID/memory/CPU limits, capped Docker logs). The proxy is attached to the upstream network only after it is healthy, and the sandbox joins only the internal network. It rejects IP literals, localhost, private/link-local/metadata addresses and cloud/test ranges (Azure WireServer, 192.0.0.0/24, 198.18/15, NAT64, 6to4, Teredo, documentation), unapproved ports and non-allowlisted hosts. For CONNECT tunnels it validates the first TLS ClientHello SNI and rejects multiple SNI names, duplicate SNI extensions, extra handshake messages, ECH and missing SNI. CONNECT :80 is rejected; plain HTTP uses per-request absolute-form validation. Only the first ClientHello is inspected, so TLS renegotiation and the encrypted inner HTTP Host remain a shared-CDN limitation (D16). An external `SANDBOX_EGRESS_PROXY` is rejected because it would reintroduce direct egress. External DNS is disabled in the sandbox (the proxy is addressed by IP and pinned in `/etc/hosts`), so DNS cannot be used as an untracked exfiltration channel; package managers still work through the proxy. Only denials are logged, rate-limited to 20/second, and Docker log size is capped for both the proxy and the sandbox. Denials are surfaced from `docker logs` when the sandbox is destroyed; live streaming of proxy logs is part of D15. The first-ClientHello probe timeout is configurable via `SANDBOX_EGRESS_PROBE_TIMEOUT_MS`. The proxy runs from the dedicated `SANDBOX_PROXY_IMAGE` (not a repo-specific sandbox image), and the supervisor explicitly clears the gated resolver test seam in the proxy environment.
- The OpenCode bash bridge binds to 127.0.0.1 with a per-run random token and is closed after the prompt. The sandbox has no route to the host loopback. In Docker mode the built-in `bash` and `shell` tools are denied and the global `sandbox_bash` tool forwards to the bridge; this is fail-closed if the custom tool fails to load. The bridge enforces the supervisor command policy and maps supervisor workspace paths to `/workspace`. Host mode keeps the built-in bash tool. There is no request ID/result cache yet (D17).
- Hostile install/test containment is covered by the real-Docker background-writer, postinstall-like lifecycle, forking-writer and sequential-exec regressions. The post-exec sweep runs five kill passes, then freezes the container, reads the init host PID with `docker inspect`, and verifies the frozen table contains nothing else before thawing. PID 1 is a childless `exec sleep`, so it cannot respawn a child, and execs are serialized per sandbox so one sweep cannot freeze another command. A survivor or unverifiable freeze/table/destroy destroys the sandbox, marks the handle compromised, and fails the exec even after cleanup; `destroy()` then refuses to report the handle as clean for the rest of the runner's lifetime, so the pre-publish gate blocks publishing even when no verification commands ran (D14, #139). CI builds the sandbox image and runs this suite against it (D13); a real npm lifecycle fixture remains future integration coverage.
- `--init` is intentionally not used: PID 1 is `exec sleep 2147483647`, a single childless process, so the frozen quiescence check can preserve exactly the init host PID reported by `docker inspect`. Zombies (which cannot fork) are ignored only when `docker top` provides a state column; any other live process stops the sandbox (D14).
- The integration tests are opt-in locally (`SANDBOX_IT_IMAGE`, plus `SANDBOX_IT_NETWORK`/`SANDBOX_IT_NETWORK_IMAGE` for egress); CI builds the sandbox and proxy images and runs `DockerSandboxRunnerIntegrationTest` against them in the `Sandbox Integration` stage (D13); `PoolManager` wiring is D8.
- NFR5 (redaction before storage): `VerificationRunner` pattern-redacts captured output (including exception messages) before truncation, and `HarnessTicketProcessor` redacts configured secrets plus high-confidence credential formats before deriving a branch name, posting ticket messages, finishing a durable run with an error, or creating a commit/PR title or PR body. The key/value rule first requires a credential keyword in the identifier via a lookahead, then matches the identifier once with a possessive quantifier. The lookahead prevents a non-credential assignment such as `{"message": "password=supersecret"}` from consuming the nested credential, and the single possessive match keeps repeated keywords linear on hostile input (64 KB/128 KB regressions). An unquoted value is redacted through end-of-line, stopping only at a quote or newline, so `password=supersecret phrase`, `password=super)secret` and non-Bearer authorization schemes are fully redacted; over-redacting adjacent text is preferred to a partial value. Multi-line private-key blocks are redacted before key/value processing so `password=-----BEGIN...` does not leave the block body unredacted. A BEGIN without an END redacts the remaining output. Credential values shorter than eight characters are not redacted by the pattern rules (and configured secrets shorter than eight characters are ignored) to avoid corrupting ordinary output. The publish gate (`SecretLeakGuard`) checks known secrets plus GitHub/OpenAI/AWS (including `ASIA`)/Slack (including `xoxc`/`xoxd`)/Google/JWT tokens and PEM/PGP/SSH2 private-key blocks; Bearer/Basic, URL-userinfo and key/value forms such as `passphrase=` are redaction-only patterns, not publish-gate formats. This is a storage guard, not a sandbox boundary; encoded, split or transformed credentials can still evade pattern matching, and provider-side telemetry is outside this slice. The scope is the OpenCode supervisor path: legacy `TicketProcessor`/`ReviewProcessor` output and externally shipped logs are **D19**. The FR11 streaming part remains D15.
