# Future Ideas

High-value improvements that were identified during deferred improvement scans but are not currently planned. These are kept here so they don't get lost in the backlog.

## Infrastructure

### S3 Migration for Planning Files
- **Source**: bp-14-ticket-planning (archived/bp-14-ticket-planning)
- **Description**: Migrate planning files from filesystem to S3. The filesystem approach won't work at scale — planning files are stored locally and don't work with multi-instance deployments.
- **Scope**: 
  - S3 bucket for planning files
  - Backend service to upload/download planning files from S3
  - Migration script to move existing files to S3
  - Configurable storage backend (filesystem vs S3 via env var)
- **Priority**: P2
- **Why deferred**: Requires S3 setup, adds AWS dependency, existing filesystem works for single-instance deployments

### CDN Caching
- **Source**: bp-11-api-caching (archived/bp-11-api-caching)
- **Description**: Add CDN-level caching for static assets (CloudFront, Cloudflare). Currently all assets are served directly from the backend/Docker containers.
- **Scope**:
  - CloudFront/Cloudflare configuration
  - Cache invalidation strategy
  - TTL configuration for static assets
  - Cache warming for frequently accessed pages
- **Priority**: P3
- **Why deferred**: Adds infrastructure complexity, current setup works for development/small deployments

## How to Use

When creating a new ticket:
1. Scan this file for relevant deferred improvements
2. If one matches, create a bp-XX ticket and remove it from this file
3. If multiple match, prioritize by impact and effort
4. If none match, check `planning/DONE/` and `planning/archived/` Out of Scope sections

## Priority Legend

- **P0**: Critical — must do before production
- **P1**: High — should do soon
- **P2**: Medium — do when capacity allows
- **P3**: Low — nice to have
- **P4**: Minimal — future consideration
