## Ticket lifecycle, phase flow & defects (intake)

Unplanned defects and flow changes found while testing (most recently on a
remote test host and in PR #168). This is an **intake list**, not a work queue:
promote an item into a `planning/<id>/` suite (then remove it here) or attach it
to an existing suite. Quality-gate enforcement is scoped to **fg-45**
(`planning/fg-45-ticket-quality-gates/`); the rows below link to it instead of
duplicating its scope.

## Infrastructure

### S3 Migration for Planning Files
- **Source**: bp-14-ticket-planning (archived/bp-14-ticket-planning)
- **Description**: Migrate planning files from filesystem to S3. The filesystem approach won't work at scale — planning files are stored locally and don't work with multi-instance deployments.
- **Scope**: 
  - S3 bucket for planning files
  - Backend service to upload/download planning files from S3
  - Migration script to move existing files to S3
  - Configurable storage backend (filesystem vs S3 via env var)
- **Priority**: P2
- **Why deferred**: Requires S3 setup, adds AWS dependency, existing filesystem works for single-instance deployments

- **Source**: bp-11-api-caching (archived/bp-11-api-caching)

- **Scope**:
  - CloudFront/Cloudflare configuration
  - Cache invalidation strategy
  - TTL configuration for static assets
  - Cache warming for frequently accessed pages
- **Priority**: P3

## How to Use

When creating a new ticket or triaging a defect:
1. Scan this file for relevant deferred improvements and defect/flow intake rows
2. If one matches, create a planning suite (or attach the item to an existing
   suite) and then remove the row, or update its **State** with the suite/PR —
   do not leave a duplicate in both places
3. If multiple match, prioritize by impact and effort
4. If none match, check `planning/DONE/`, `planning/archived/` Out of Scope
   sections and the deferred registers in `00_ARCHITECT_CHECKLIST.md`
5. For ticket-lifecycle rows, check `planning/fg-45-ticket-quality-gates/` first —
   it is scoped to Definition of Ready and execution gating

## Priority Legend

- **P0**: Critical — must do before production
- **P1**: High — should do soon
- **P2**: Medium — do when capacity allows
- **P3**: Low — nice to have
- **P4**: Minimal — future consideration
